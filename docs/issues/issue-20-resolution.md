# Issue #20 答复草稿

感谢这份非常耐心的报告。你后来对最初判断的纠正——正确的模型是"复用原来的树并原地
同步"，而不是"重扫在某个条件下踩到了坑"——就是这次修复的设计前提，我们按这个前提
实现，没有走"猜一个条件然后打补丁"的路。

下面按你提的五点逐条对应。

## 1. 幂等导入与重扫

目录来源的身份现在是"知识库 + 规范化真实路径"（真实路径即 `realpath`，macOS 的 `/var`
符号链接、Windows 的 junction 与短名都归一到同一个身份）。再次导入同一目录会复用原来
的根容器并原地同步。

首次导入、重复导入、单文件重建、整库后台重建这四条路径现在共用同一个 diff 引擎——以前
它们各自维护状态，这正是"重扫报告了它没有做的事"和"整库后台重建完全跳过已跟踪的根"的
来源。

目录内的文件按"目录来源 + 相对路径"匹配。历史遗留、没有记录路径的子项，只有在名称和
类型都唯一时才会被认领；出现两个候选就报 `ambiguous_source`。

## 2. 诚实的返回值

每次导入和目录重扫都逐项返回 `created` / `updated` / `unchanged` / `deleted` /
`failed`（带相对路径），并给出汇总状态 `synced` / `unchanged` / `partial`。

- 未变化的文件不再算失败——你那条 `ok:false ... duplicate document` 的根因就是这个。
- 大部分成功、个别失败时返回 `partial`，并保留已经完成的同步，不再把一次基本成功的
  操作整体报成失败。
- `imported` 现在计的是"新建 + 更新"，所以"重扫确实改了文件却回 `imported: 0`"也不会
  再有。
- 容器的 chunk 计数不再独自承担说明责任：重扫返回的是逐项结果（`items`）。
- 客户端传错参数现在回 400 而不是 500。

## 3. `sourcePath` 进入文档 API

目录容器的 `sourcePath` 会在首次同步时写入，管理侧的文档摘要与详情都能读到，客户端
因此可以在删除之前判断哪个容器才是目录来源。模型可见的检索结果里不会带它，避免把
服务器绝对路径泄漏进检索证据。

另外新增只读预检 `GET /knowledge/documents/:id/delete-impact`，报告这次删除会移除的
目录、文件、分块与原始快照。

## 4. 更新流程写进文档

中英文 README 都补充了"更新已导入目录的正确方式"：重新导入同一路径，或对目录容器执行
重扫——两者走同一条同步路径，都只原地更新原来那棵树；同时说明了身份规则以及
`ambiguous_source` 的处理方式。文件级重建仍然按设计只重放已保存的快照（这一点你在
Evidence 里已经确认），但 README 现在明确写出：更新目录来源请重扫目录容器，或重新导入
同一路径。

## 5. 删除级联护栏

删除非空目录现在必须显式传 `recursive: true`，否则返回
`recursive_confirmation_required`。界面会先取 `delete-impact` 预检，再用第二个确认
对话框列出将被删除的确切范围；`knowledge_delete_document` 工具暴露同一个参数。批量
删除会在写入任何东西之前预检全部根，所以"少一个确认"不可能留下半删状态。

你那次"删掉看起来重复的根，静默带走了刚导入的 README 及其原始快照（8 → 5 文档）"，
在 4.0.0 下会先停下来让你确认。

## 关于你已经存在的重复树

按你说的"不能靠猜"，我们**没有**自动清理：已经存在的重复树不会被合并、移动或删除，
只会报告 `ambiguous_source` 并附上候选 id。请手动检查后删掉多余的那一棵——现在删除
会先给出影响预检和第二次确认。

## 请你确认

如果方便，请在你那个干净基线上再跑一遍：

1. 连续两次导入同一目录：第二次预期返回 `status: "synced"` 或 `"unchanged"`，并且
   仍然只有一棵根树；
2. 改动其中一个文件再重扫：预期同一个文档 id 被原地更新，不产生新文档；
3. 对目录容器 `POST /knowledge/documents/reindex`：现在返回的是逐项结果，而不是一句
   `ok:false`。

身份复用、`ambiguous_source` 判定、逐项结果和 `recursive` 闸门都有回归测试锁定，但你的
环境（Linux + 真实目录 + 你自己的历史数据）是我们无法在这里完全模拟的。确认无误后，
这个 Issue 就可以按已完成关闭。
